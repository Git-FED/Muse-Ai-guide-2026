# Muse User Guide

## Welcome

Muse is an AI guide for thinking, creating, organizing, researching, and building with more clarity. This repository teaches the ideas progressively, from foundations through a capstone project.

## Quick start

1. Read [Getting Started](docs/getting-started.md).
2. Review the [Curriculum](CURRICULUM.md).
3. Begin with [Lesson 00 — Orientation](lessons/00-orientation/README.md).
4. Use the worksheet to write a goal, context, constraints, and verification plan.
5. Move through the lessons in order or jump to the module that matches your experience.

## The Muse method

For almost any task, use this loop:

1. **Outcome:** What should be true when the task is done?
2. **Context:** What does Muse need to know?
3. **Constraints:** What must be included, avoided, or preserved?
4. **Draft:** Ask Muse for a first useful version.
5. **Inspect:** Check facts, assumptions, safety, privacy, and formatting.
6. **Revise:** Tell Muse exactly what should change.
7. **Verify:** Confirm the final result meets the original outcome.

## How to write a strong request

Use this pattern:

```text
Goal: [desired result]
Context: [relevant background]
Constraints: [limits, rules, tone, format]
Input: [material Muse should use]
Output: [exact format]
Verification: [how we will know it is good]
```

## Working with memory

Memory should be durable, relevant, and editable. Prefer summaries over transcripts. Do not use real secrets, private account data, or unnecessary personal information in lessons. When Muse remembers something incorrectly, correct it directly and record the correction in the appropriate context.

## Working with tools and agents

Start with the smallest useful action. Name the target, destination, permissions, and success evidence. Use previews or dry runs before external writes. Never treat access to a tool as permission to use every capability.

## Safety and privacy

- Treat important output as a draft until checked.
- Keep credentials out of prompts, files, screenshots, and repositories.
- Use synthetic or sanitized examples in class exercises.
- Verify the destination before publishing or changing data.
- Ask for human approval before consequential external actions.

## Suggested learning paths

- **Beginner:** Foundations → Prompting → Memory and Context
- **Builder:** Prompting → Agents → Integrations → Building with Muse
- **System designer:** Architecture → Safety, Privacy, and Ethics → Project Week → Capstone
