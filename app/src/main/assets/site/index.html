01

Put a ruler in the room before you send an agent into the world.

Most “usage” reports collapse a multi-step job into one vague number. This project refuses that shortcut. Define the unit. Capture the evidence. Label the gap.

Count actions, not vibes.

A search, page load, upload, form fill, model call, and download are separate events. Each receives an ID and a timestamp.

Separate the instruments.

Network bytes and model tokens are different measurements. Keep input, output, reasoning, cache reads, and latency in their own lane.

Make uncertainty visible.

Measured, reported, estimated, and unavailable are not synonyms. A useful ledger tells the reader which one they are looking at.

02

The page is a small control room.

Use the same vocabulary in the setup prompt, the interim table, the final report, and the conversation around it.

ACTION
what happened?
EVIDENCE
what can we prove?
REPORT
what should change?

From prompt to operating rhythm.

The included prompt starts in Data Usage Audit Mode. It asks the agent to make a ledger entry before moving to the next action, then surfaces a compact interim table after every five actions.

  • Ask before sign-in, upload, download limits, or form submission.
  • Record category and size instead of retaining sensitive content.
  • Stop before an action expected to exceed the agreed data threshold.
  • End with totals by action type, service, and evidence quality.
